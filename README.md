# 生産管理

ゲームの生産ツリー、必要素材、施設数をブラウザで見るツールです。データは `data/*.yaml` を手で編集します。

## 起動

```powershell
go run .
```

ポートとデータディレクトリを変えるときは `go run . 8080 data` です。起動すると、このPC用の `http://localhost:8080/` と、同じネットワークの端末から開く URL を表示します。`/` がホスト、`/client` がクライアントです。画面上部の「接続」から、クライアントを開くQRコードを表示できます。

ゲーム、アイテム、目標速度はサーバに1つだけあり、どちらの画面で変えても、約1秒以内にもう一方へ出ます。種類と名称の絞り込み、必要素材の表示切替、テーマ、拡大表示、現在個数のメモは、その画面だけに残ります。

## 画面

ゲーム、種類、名称でアイテムを絞り、アイテムを選ぶと生産ツリーが出ます。完成品が上、材料が下です。生産ツリーはホストだけに出ます。クライアントはゲーム、種類、名称、アイテムの選択と、必要素材、必要施設数、目標速度の表示ができます。

目標速度は「1秒あたり何個か」です。空欄のときは、選んだアイテムの先頭レシピが1回で出す個数を速度として使います。`0.5` のように小数も入れられます。

必要素材の「すべて」は原材料と中間素材の両方です。「1次素材のみ」は、採取や採掘のように先頭レシピの材料が空の行だけです。個数に端数があるときは、表示で切り上げます。各行の「現在」欄には手持ちの個数をメモでき、必要個数を超えた行は暗く表示されます。メモはブラウザに保存され、端末間では共有しません。

必要施設数は、目標速度を1台あたりの産出速度（個/秒）で割って切り上げた台数です。生産時間が無いアイテムは施設数を出さず、その旨を表示します。必要素材の表示では、生産時間が無くても必要個数を出します。

ツリーと一覧は、それぞれ「拡大」でブラウザの画面いっぱいに広げられ、Esc で戻ります。素材と施設の一覧では、アイコン画像がある行だけ名前の左にアイコンを出します。

## データを直す

ゲームの追加・修正・削除は、`data` 直下の `.yaml` または `.yml` を手で編集します。画面からは変えられません。ファイルは起動時に読むので、保存したらツールを止めて起動し直します。開いたままの画面は、再起動後もそのまま同期を続けます。

各ファイルの `name` が画面のゲーム名、拡張子を除いたファイル名がゲームIDです。アイコンは `data/icon/<ゲームID>/<アイテムID>.png` に置きます。1つのアイテムにレシピが複数あっても、使うのは先頭のレシピだけです。

壊れたファイルは読み込まず、画面上部にファイル名と内容を表示します。ほかのゲームの読み込みは止まりません。キーの打ち間違いも、ファイル上の行番号付きでエラーになります。

## ソースから作る

Go 1.27.2 以降が必要です（`go.mod` の指定）。リポジトリのルートで次を実行します。

```powershell
go build -o game-production-manager.exe .
go test ./...
```

配布用のzipは、`package.bat` を実行すると `dist\game-production-manager.zip` にできます。`tools/` の Go ファイルはデータ作成用の単発スクリプトで、`go build ./...` には含まれません。実行するときは `go run tools/analyze.go` のようにファイルを指定します。
